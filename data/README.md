# data/ — CSV 레이아웃

16테이블 스키마(`src/create_schema/`)에 넣을 값. **파일 1개 = 테이블 1개**이고
헤더는 DDL 의 컬럼명·순서 그대로다.

```
data/master/*.csv ┐
                  ├─[load_csv.py]─> user.db
data/seed/*.csv   ┘     ▲
      ▲                 └ animal_categories / product_categories / feeding_purposes
      └─[gen_seed.py]     는 여기 없다. 코드(*_schema.py 의 SEEDS)가 넣는다.
```

실행 순서:

```bash
py src/make_data/gen_seed.py   # data/seed/*.csv 재생성 (시드 고정)
py src/load_csv.py             # 스키마 재생성 + 적재 + 검증
```

---

## 세 갈래로 나눈 이유

| 갈래 | 무엇 | 누가 채우나 | 재생성 |
|---|---|---|---|
| **코드 SEEDS** | `animal_categories`, `product_categories`, `feeding_purposes` | `*_schema.py` | 스키마와 함께 |
| **`data/master/`** | `allergens`, `breeds`, `ingredients`, `ingredient_allergens` | 사람 | **하지 않는다** |
| **`data/seed/`** | 나머지 9테이블 | `gen_seed.py` | 언제든 |

**마스터를 재생성하지 않는 것이 이 구분의 핵심이다.** `allergen_id` 가 한 번 바뀌면
손으로 넣은 `ingredient_allergens` 매핑이 통째로 어긋난다 — 에러 없이, 조용히.
생성기는 마스터를 **읽기만** 한다.

코드 SEEDS 에 있는 3개를 CSV 로 또 빼지 않는 이유는 같은 값이 두 군데 앉기 때문이다.
행이 2~6개라 코드에 두는 비용이 없다.

'알러지원 없음'으로 읽히므로(2026-08-24 에 `allergen_reviewed` 를 뺀 뒤의 fail-open),
**원료를 추가할 때 매핑을 같이 넣지 않으면 그 원료가 든 제품이 `Safe` 로 통과한다.**

`allergens.csv` 의 행 순서는 지켜도 되고 안 지켜도 된다 — 로더가 `parent_id` 를 보고
부모부터 넣도록 정렬한다. 순환 참조는 그 자리에서 거부한다.

## CSV 규약

- **다중값 컬럼을 만들지 않는다.** 옛 `pet_products.ingredients` 의 `'닭고기|현미|오메가3'`
  같은 파이프 구분은 연결 테이블 행으로 푼다. 정규화한 이유가 그것이다.
- **NULL 은 빈 칸.** 로더가 `'' -> None` 으로 바꾼다.
- **UTF-8, BOM 없음, 개행 LF.** 옛 `data/pet_*.csv` 4종에는 BOM 이 붙어 있으니 섞지 않는다.
- **값 캐스팅을 로더가 하지 않는다.** STRICT 테이블이 `'30000'` 은 INTEGER 로 받고
  `'삼만원'` 은 거부한다. 파이썬에서 `int()` 를 먼저 부르면 같은 검사를 두 번 하는 셈이다
  (근거: `execute_schema.py` 설계규칙 7번).

## DB 가 막지 못해 생성기가 책임지는 것

`docu/schema/` 가 "앱이 막는다"로 적어둔 것들이다. 데이터를 손으로 고치거나 생성기를
바꿀 때 여기서 어긋나면 **에러 없이 조용히 틀린다.**

**① `pet_allergies` 펼침** — 카테고리를 고르면 하위를 전부 넣고 **고른 카테고리 행도 남긴다.**
`가금류` 를 고른 개체는 `가금류`/`닭고기`/`오리`/`칠면조` 4행이다. 카테고리 행이 있어야
나중에 `거위` 가 추가됐을 때 대상을 찾을 수 있다.

**② 축종 정합성** — 개 `pet` 에 고양이 `breed` 를 붙여도 FK 는 통과한다. 생성기가
`BREEDS_BY_CATEGORY` 로 막는다. `product_animal_categories` 도 같다.

**③ 판정 3분법이 실제로 관측되도록 분포를 섞는다.** `ingredients_verified = 0` 인 제품과
`product_animal_categories` 0행 제품을 일부러 남긴다. 전부 `1` / 전부 1행이면
`v_product_safety` 의 `None`(판정불가) 분기가 한 번도 안 나와서, 스키마는 멀쩡한데
검증만 헛돈다. 현재 실측:

```
v_product_safety 전체: Safe 33920쌍 / None 11862쌍 / WARN 5477쌍
활성 펫 402마리 중 Safe 후보 0개인 펫 3마리
```

**Safe 후보 0개인 3마리는 버그가 아니다.** 셋 다 `단백질` 최상위 노드를 골라
육류·어류·갑각류·유제품·난류가 통째로 배제된 개체다(알러지 25행). 실제로 일어나는
상황이고, 이 경우 앱이 무엇을 보여줄지는 아직 정하지 않았다.

`load_csv.py` 가 적재 후 위 두 줄을 매번 출력한다. 한 종류로 쏠리면 경고한다.

## 문서가 요구한 케이스를 데이터가 담고 있는가

**스키마가 어떤 구조를 고른 데는 이유가 있고, 그 이유는 대개 "이런 경우가 있으니까"다.**
그 경우가 데이터에 하나도 없으면 구조는 있는데 한 번도 시험되지 않는다. `docu/schema/` 의
4개 문서에서 그런 진술을 뽑아 실측한 결과다.

| 문서 | 문서가 말한 것 | 데이터 |
|---|---|---|
| `product_schema.md` | 복합 원료는 알러지원을 여러 개 갖는다 — `'베이커리 부산물'`은 밀·계란·유제품 | 복합 원료 **5종** |
| `product_schema.md` | 소형견 전용 = `target_size_min 2, max 2` | `min == max` 제품 **14개** |
| `product_schema.md` | `description` 은 후기 없는 신규 제품(콜드스타트)의 임베딩 대상 | 축종·체구·연령·주원료·목적을 한 문장에 |
| `user_schema.md` | 같은 uid 라도 제공자가 다르면 다른 계정이다 | 제공자만 다른 uid **15쌍** |
| `user_schema.md` | `phone` 에 UNIQUE 를 안 건다 — 가족 공유, 번호 재할당 | 중복 번호 **14개** |
| `common_schema.md` | `allergens.name_eng` — 영문명. 없으면 NULL | NULL **2행**(도라지·더덕) |
| `pet_schema.md` | `breeds.name_eng` 가 NULL 인 품종이 공존한다 | NULL **2행**(삽살개·풍산개) |
| `pet_schema.md` | `pet_breeds` 0행 = 모름 / 2행 이상 = 믹스 | 0행 **42** / 2행+ **71** |
| `product_schema.md` | `product_nutrition` 은 결측 때문에 분리했다 | 성분표 없는 제품 **36개** |

**복합 원료가 이 중 제일 중요하다.** `ingredient_allergens` 가 컬럼 하나가 아니라 다대다
테이블인 **유일한 이유**가 이것이고, 전부 1:1 매핑이면 컬럼 하나로 둔 설계와 결과가 같아진다.
실제로 지금 데이터에서 **복합 원료 때문에 위험 판정된 쌍이 1,400여 개**다 — 컬럼 하나였다면
그중 상당수가 조용히 `Safe` 로 통과했다.

```
베이커리부산물 -> 우유, 계란, 밀
가금부산물분   -> 닭고기, 오리, 칠면조
어분           -> 연어, 참치, 대구
혼합곡물분     -> 밀, 보리, 옥수수
동물성유지     -> 닭고기, 소고기
```

## 조인했을 때 앞뒤가 맞는가

행 하나만 보면 멀쩡한데 **두 값을 같이 보면 틀린** 것들이다. FK 도 CHECK 도 못 잡는다.
`gen_seed.py` 가 값을 뽑는 순서로 막는다 — 뒤에 오는 사건은 앞선 사건을 하한으로 삼는다.

| 규칙 | 왜 |
|---|---|
| `users`: 가입 → 로그인 → 탈퇴 → 수정 | **탈퇴한 뒤에는 로그인할 수 없다.** 그래서 `withdrawn_at` 은 `last_login_at` 이후로만 뽑는다 |
| `pets`: max(생일, 주인 가입) → 등록 → 활동종료 → 수정 | 하한이 **두 개**다. 주인 가입일만 보면 태어나기 전에 등록된 개체가 생긴다 |
| `products`: 등록 → 수정 | 둘을 따로 뽑으면 절반이 '3년 전에 수정됨'이 된다 |
| 100g당 가격 = `price_krw` / `weight_g` | 가격을 중량과 따로 뽑으면 이 파생값이 무의미해진다. **중량을 먼저 뽑고 단가를 곱한다** |

**시각까지 순서를 맞춘다.** 날짜만 뽑고 시:분:초를 나중에 무작위로 붙이면 같은 날일 때
`09:00` 가입 → `03:00` 로그인이 나온다. `rdt()` 가 초 단위로 뽑아서 이 구멍을 없앤다.

실측 (2026-08-26 기준, 전부 0건이어야 한다)

```
시간 역전 14종 검사 ....... 0건
미래 시각(2026-08-25 초과) . 0건
```

100g당 가격은 제형 안에서 **1.6~3.6배**로 좁혀졌고, 제형 사이 차이(건식 738원 ↔ 동결건조
9,412원)는 실제 시장과 같은 방향이다. 대용량 할인도 걸린다 — 건식 사료 7kg↑ 610원 /
1~3kg 958원.
