# 측정 기록

채점기가 낸 숫자를 **잰 날짜·표본·모델과 함께** 옮겨 적는 자리.

왜 따로 적나. `data/eval/runs.jsonl` 에 실행마다 한 줄씩 쌓이지만 그건 기계가 읽는
것이고, "그래서 무엇을 알게 됐나"는 안 남는다. 숫자만 남으면 반년 뒤에 그 숫자가
좋은 건지 나쁜 건지 아무도 모른다.

**규칙**: 표본 수와 모델을 안 적은 숫자는 여기 못 적는다. 비교가 안 되기 때문이다.

```bash
python -m eval all              # 요금 안 드는 것만 (qa_check · golden)
python -m eval all --with-llm   # 넷 다. 표본을 작게 잡아도 요금이 나간다
```

## 2026-09-04 · 로컬 · e5-small(384차원)

- 임베딩 `intfloat/multilingual-e5-small` · 색인 조각 1,818개
- LLM `qwen2.5:3b` (Ollama) — **이날은 못 띄워서 LLM 채점 두 개는 못 쟀다**

### qa_check — 짧은 질문으로 후보를 가져오나 (22문항 · k=5)

| 지표 | 값 |
| --- | --- |
| 골든셋 자가검증 어긋남 | 0 / 22 |
| hit@5 | 90.9% |
| precision@5 | 69.1% |
| 축종이 어긋난 후보 | 0 / 110 |
| **알레르기 위반** | **0 / 20** |

읽는 법. hit@5 가 91% 인데 precision@5 는 69% 다. 화면에 5개를 보여주면 그중 1~2개는
조건에 안 맞는 것이 섞인다는 뜻이다. 사용자가 체감하는 쪽은 precision 이다.

알레르기 위반 0 건은 품질이 아니라 **안전** 칸이다. 여기가 0 이 아니면 그건 점수가
낮은 게 아니라 버그다.

못 맞힌 문항 2개 — 4번(소화·생식), 12번(고양이 신장). 둘 다 조건을 만족하는 상품이
DB 에 있는데(자가검증 통과) 상위 5개 안에 못 들어왔다.

**원인은 아직 안 밝혔다.** 조각 텍스트에 급여목적이 `(소화 목적, 생식)` 처럼 한 번만
들어가서 긴 리뷰 본문에 신호가 묻히는 것이 아닌가 의심하고 있지만, 확인 안 한 추측이다.
그 두 문항의 조각을 직접 열어 보기 전에는 여기 원인으로 적지 않는다.

### golden — 홀드아웃 리뷰로 원래 상품을 되찾나 (182건 · top50)

| 지표 | 값 |
| --- | --- |
| recall@1 | 14.8% |
| recall@3 | 24.2% |
| recall@10 | 39.0% |
| MRR | 0.229 |
| 질의 인코딩 | 18.1 ms |
| **recall@3 95% 구간** | **18.1% ~ 30.8%** |

**이 표에서 제일 중요한 줄은 마지막이다.** 방법을 하나도 안 바꾸고 표본만 다시 뽑으면
recall@3 이 18.1% 에서 30.8% 사이를 왔다 갔다 한다. 폭이 12.6%p 다. 모델을 바꿔서
recall@3 이 24% → 28% 가 됐다면 그건 **개선이 아니라 운**이다. 홀드아웃이 182건뿐이라
1건이 0.5%p 라서 그렇다.

top50 미스 57건 중 8건(14.0%)은 알레르기 필터가 **정답 자체를 걸러낸** 것이다. 검색이
못 찾은 게 아니라 애초에 못 찾게 되어 있는 표본이라, 이 14% 는 검색을 아무리 고쳐도
안 줄어든다. 진짜 천장은 39% 가 아니라 그보다 위다.

### format_check — 못 쟀다

Ollama 가 안 떠 있고 `.env` 에 `USE_API=1` 도 없어서 LLM 호출이 전부 실패한다.
`require_llm()` 이 채점을 시작하기 전에 막았다.

```
ollama serve  후  ollama pull qwen2.5:3b     # 로컬로 재려면
.env 에 USE_API=1 과 LLM_API_KEY            # 상용 API 로 재려면
```

같은 이유. ragas 자체는 깔려서 import 된다(`ragas 0.4.3` + `langchain-community 0.3.31`).

## 다음에 잴 때 볼 것

1. **format_check 세 조건을 나란히.** `지시만 / 예시추가 / 스키마 강제` 중 어디서
   JSON 성공률이 꺾이는지. 3B 짜리 로컬 모델은 스키마를 걸어도 개수(5개)를 자주 틀린다.
   틀린 만큼 `recommending.recommend()` 가 재시도로 메우고 있고, 그 재시도는 요금과
   응답 시간으로 나간다. **점수가 같아도 재시도가 늘었으면 나빠진 것이다.**
2. **ragas_check 의 1번 표를 먼저.** 후보 밖 상품 언급이 0 인데 faithfulness 가 낮으면
   우리 답이 아니라 심판을 의심할 차례다. 심판도 LLM 이라 틀린다.
3. **모델을 바꿔 재보기.** `EMBED_MODEL` 을 바꿔 재색인하고 `python -m eval golden` 을
   돌린 뒤 `python -m pipeline.eval.compare` 대신 `python -m eval.compare` 로 짝지어
   비교한다. 총점 차이는 위 12.6%p 안에 묻히므로, 표본별로 누가 어디서 이겼는지를 센다.
