### 1. load_db.py — 적재 실패 원인 수정

`pet_purchases.csv`가 10 → 17 컬럼으로 갱신됐는데 테이블 정의는 10 컬럼 그대로여서
실행 시 크래시하던 상태였다 (직전 커밋 `wip : fixing db`). 누락 컬럼 7개를 추가했다.
`breed`, `size_category`, `weight_kg`, `age_group`, `age_years`, `allergy`, `health_condition`

`user.db`에 남아 있던 데이터도 옛 버전이었다 (리뷰가 "잘 먹는 편이에요." 수준의 짧은 문장).
현재 CSV의 리뷰는 훨씬 길고 구체적이라 재적재가 필요했다.

같이 손본 것

- 테이블 정의를 `SCHEMAS` 딕셔너리 하나로 통합. DDL / INSERT 컬럼목록 / 타입변환이 여기서 파생된다.
  세 곳을 따로 관리하다 어긋난 게 이번 문제의 원인이라 단일 원천으로 묶었다.
- CSV 헤더가 스키마와 다르면 즉시 `ValueError`. 같은 사고가 조용히 반복되지 않게 한다.
- 숫자 컬럼을 INTEGER/REAL로 캐스팅. 이전엔 전부 문자열이라 `price <= budget` 비교가
  사전순으로 동작해 틀린 결과가 나올 수 있었다.
- 프로필 조건 검색용 인덱스 4개 추가.

### 2. embed.py — 애견 리뷰 임베딩으로 재작성

대상 변경: `selectory.db` / `purchases` / `category='Cosmetics'` → `pet_reco.db` / `pet_purchases`

- **holdout 404건 제외**. 평가용으로 빼둔 행이라 색인에 넣으면 성능 측정이 오염된다.
  → 색인 대상 1035건, 384차원.
- 리뷰 본문 앞에 반려견/상품 컨텍스트를 붙여 임베딩.
  예: `소형견 시니어 비숑프리제, 알레르기 없음, 관절이 약함. 사료/실버사료 ... 별점 2점 후기: ...`
- `review_vectors`에 `doc` 컬럼 추가 (근거 제시·디버깅용), `embedding_meta`에 모델명/차원 기록.

### 3. 확인된 사항 — 벡터 유사도만으로는 조건이 지켜지지 않음

질의: `"닭고기 알레르기가 있는 소형견인데 피부 가려움에 괜찮았던 사료"`

```
1) 벡터 유사도만        → 상위 3건이 전부 대형/중형견
2) 프로필 필터 + 벡터   → 소형견 리뷰만
```

`build_doc()`에서 체급·견종을 문장에 넣어도 마찬가지다. 임베딩은 의미적 유사만 볼 뿐
조건을 강제하지 못한다. **알레르기처럼 틀리면 안 되는 조건은 반드시 SQL로 걸러야 한다.**

추천 API도 `프로필 SQL 선필터 → 벡터 랭킹` 순서를 따라야 한다. `search()`에 이 패턴을 구현해뒀다.

### 4. 스키마 정리

- DB 이름 `user.db` → `pet_reco.db`. 회원 정보만 든 게 아니라 서비스 데이터 전체라 이름이 안 맞았다.
- ID 컬럼을 TEXT → INTEGER 전환 (`C0001` → `1`). 접두어는 컬럼명으로 복원 가능해 정보 손실이 없다.
  `SCHEMAS`에 표시용 타입 `ID`를 두어 DDL 생성과 접두어 제거를 한 곳에서 처리한다.
  화면 출력만 `fmt_purchase_id()`로 `O00418` 형태로 되돌려 디버깅 가독성을 유지했다.
- `.gitignore`에 `*.db` 추가. CSV에서 언제든 재생성되는 산출물이라 추적하지 않는다.

### 남은 과제

- **더미데이터 불일치**: `건식사료` 상품인데 `target_food_form`이 `습식`이거나,
  `중형견 비글` 리뷰 본문에 "소형견이라..."가 들어있는 행이 있다.
  RAG 근거로 쓰면 LLM이 모순된 답을 만든다. 데이터 생성 로직 점검 필요.
- **토큰 잘림**: 현재 모델 입력 한도가 128 토큰인데 문서 평균이 97 토큰이고 3건(0.3%)이 잘린다.
  리뷰가 길어지면 비율이 오르고, 하필 뒷부분에 결론("재구매 의사 있어요")이 오는 경우가 많다.
- **모델 교체 검토**: 현재 `paraphrase-multilingual-MiniLM-L12-v2`는 대칭적 유사도용이다.
  이 프로젝트는 짧은 질의로 긴 리뷰를 찾는 비대칭 검색이라 `intfloat/multilingual-e5-small`
  (512 토큰, 384차원, 검색용 학습) 쪽이 구조적으로 맞다. 단 `query:` / `passage:` 접두어 규약 필요.
  → 질의를 바꿔가며 테스트해본 뒤 판단하기로 함. 지금은 보류.
- **저장 형식**: 벡터를 JSON 문자열로 저장 중이라 8.3MB. float32 BLOB이면 1.5MB.
  지금 규모에선 체감 없으나 데이터가 늘면 먼저 손볼 곳.
- **명소 추천 데이터** 미착수 (GOAL 필요데이터 항목).
