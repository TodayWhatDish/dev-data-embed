## 1. LLM 입력 토큰 — 약 90% 절감

답변 모델에 상품 자료를 통째로 넣지 않습니다. 축종 · 체급 · 알러지로 **먼저 거르고**(SQL),
그 안에서 벡터 검색 상위 20개만 넘깁니다.

측정일 2026-09-29 · 고객 1명(개 · 소형 · 닭고기 알러지) · `build_answer_context` 결과를 `tiktoken o200k_base`로 계산

| 질문 | 전체 상품 182개 | 조건 필터 후 56개 | 실제 `/ask` (상위 20개) | 절감률 |
|---|---:|---:|---:|---:|
| 입이 짧은 아이한테 맞는 사료 추천해줘 | 26,616 | 8,081 | **2,701** | −89.9% |
| 피부에 좋은 간식 알려줘 | 26,861 | 7,893 | **2,727** | −89.8% |
| 소화 잘 되는 사료 뭐가 있어? | 27,116 | 8,298 | **2,906** | −89.3% |

- 조건 필터만으로 약 −70%, 여기에 검색 상위 20개 제한을 더하면 약 −90%입니다.
- 알러지 성분이 든 상품은 이 단계에서 이미 빠지므로 LLM이 실수로 추천할 여지도 없습니다.

## 2. 검색 품질 — recall@3 12.7% → 25.8%

후기 문장으로 해당 상품을 찾아내는지 봅니다. 홀드아웃 후기를 질의로 쓰고, 정답 상품이 상위 3개 안에 들면 적중입니다.

| 날짜 | 변경 | recall@3 |
|---|---|---:|
| 2026-08-29 | 기준 (8/63) | 12.7% |
| 2026-08-29 | 문서에서 모든 상품에 똑같이 붙는 프로필 문구 제거 | 14.3% |
| 2026-08-29 | 시드 데이터에 원료 슬롯 추가 | 19.7% |
| 2026-08-31 | 평가 스크립트에 빠져 있던 축종 필터 추가 | 18.2% → 21.2% |
| 2026-08-31 | 후기 문서에 원료 목록 포함 (16/66) | **24.2%** |
| 2026-09-01 | 오래된 색인 발견 → 재색인 | 19.7% → **25.8%** |

- 상위 50개 안에도 못 드는 실패 건: 30 → 27건.
- 평가 스크립트의 필터 누락도 이 과정에서 찾아 고쳤습니다. 서비스와 같은 조건으로 재야 수치가 의미 있습니다.

## 3. 평가 신뢰도 — 신뢰구간 폭 21.2%p → 8.7%p

표본이 적으면 수치 몇 %p 차이는 우연일 수 있습니다. 홀드아웃을 늘려 판단 근거를 단단하게 했습니다.

|---|---:|---:|
| 이전 | 66건 | 21.2%p |
| 이후 | 275건 | **8.7%p** |

## 4. 임베딩 모델 선정

### 4-1. 로컬 모델 3종 비교

같은 조건(홀드아웃 275건 · 색인 1,764조각)으로 비교했습니다.
판정 규칙은 측정 전에 정했습니다: **MRR 주지표, 신뢰구간이 겹치면 동률, 동률이면 차원이 낮고 빠른 쪽.**

| 모델 | 차원 | r@1 | r@3 | r@10 | MRR | 질의 시간 | 벡터 용량 |
|---|---:|---:|---:|---:|---:|---:|---:|
| **e5-small** | 384 | 8.7% | 18.9% | 34.9% | **0.1745** | **13.8ms** | **2.6MB** |
| e5-base | 768 | 10.2% | 17.8% | 30.5% | 0.1690 | 41.3ms | 5.2MB |
| bge-m3 | 1024 | 6.9% | 18.9% | 36.4% | 0.1643 | 131.6ms | 6.9MB |

짝지은 부트스트랩(4,000회)으로 본 MRR 차이의 95% 구간:

| 비교 | 차이 | 95% 구간 | 판정 |
|---|---:|---|---|
| small → base | −0.0055 | [−0.0299, +0.0187] | 동률 |
| small → m3 | −0.0101 | [−0.0385, +0.0180] | 동률 |
| base → m3 | −0.0047 | [−0.0327, +0.0216] | 동률 |

→ 세 모델은 통계적으로 차이가 없어서, **bge-m3보다 9.5배 빠르고 용량이 1/2.6인 e5-small**을 골랐습니다.
지표마다 1등이 다른 것(r@1은 base, r@10은 m3)도 노이즈로 판단했습니다.

**데이터 천장:** 후기 문장 10,432개 중 서로 다른 문장은 1,603개뿐이고, 후기의 51.3%에는 상품 고유 문장이 없습니다.
모델을 바꿔도 점수가 크게 오르지 않는 이유가 여기에 있습니다.

### 4-2. e5-small(로컬) vs OpenAI text-embedding-3-small — 트레이드오프

배포(Railway 무료 플랜)에서 로컬 모델을 담으면 이미지가 너무 커서 OpenAI 임베딩으로 옮겼습니다.
**검색 점수는 오히려 낮게 나왔고**, 그대로 적습니다.

| | e5-small (09-04) | text-embedding-3-small (09-26) |
|---|---:|---:|
| golden 홀드아웃 | 182건 | 270건 |
| recall@1 | 14.8% | 10.0% |
| recall@3 | 24.2% | 18.9% |
| recall@10 | 39.0% | 35.2% |
| MRR | 0.229 | 0.176 |
| 질의 시간 | 18ms (로컬) | 167ms (API 왕복) |
| qa_check hit@5 (22문항) | 90.9% | 77.3% |
| qa_check precision@5 | 69.1% | 35.5% |
| 축종 어긋남 / 알러지 위반 | 0 / 0 | **0 / 0** |

- 두 측정은 홀드아웃 표본 수가 달라(182 vs 270) 1:1 비교는 아닙니다.
- **안전 지표(축종 · 알러지 위반)는 두 모델 모두 0건**입니다. 거르기는 SQL이 하므로 임베딩 모델과 무관합니다.
- 전환 이유는 5절의 배포 용량입니다. 로컬 모델은 `local` extra로 남겨 두어 언제든 되돌릴 수 있습니다.

## 8. 체감 응답 속도 — 스트리밍

답변을 다 만든 뒤 한 번에 보내지 않고, NDJSON으로 **근거 → 답변 글자 → 반증** 순서로 흘려보냅니다.
사용자는 근거 상품 카드를 먼저 보고, 답변이 타이핑되듯 이어집니다.

측정일 2026-09-29 · 로컬 서버 · 1절과 같은 3개 질문 · `gpt-4o-mini`

| 이벤트 | 질문 1 | 질문 2 | 질문 3 | 중앙값 |
|---|---:|---:|---:|---:|
| 근거(`sources`) 도착 | 3.14s | 1.23s | 0.98s | **1.23s** |
| 답변 첫 글자(`delta`) 도착 | 4.71s | 2.93s | 1.93s | **2.93s** |

- 첫 질문이 느린 것은 콜드 스타트(캐시 적재) 영향입니다.
- 답변 완료 · 반증까지의 전체 시간은 이번 측정에서 반증 API 호출이 인증 오류로 실패해 **신뢰할 수 없어 싣지 않았습니다.**
- 화면 쪽은 수치 대신 동작으로 확인했습니다: 근거 먼저 표시, 상품과 무관한 질문에는 추천 카드 숨김.
